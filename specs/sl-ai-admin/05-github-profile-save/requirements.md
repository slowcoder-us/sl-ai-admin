# GitHub 用户保存与列表（Web） - 需求

> 来源：`docs/首页需求.md` · 2.2 加入数据库、2.3 已保存列表、2.6 访问控制、4 交互要求
> 依赖：04-github-profile-search

## 背景

搜索到的 GitHub 用户需要加入数据库，并在后台持续可见。本 feature 提供数据表、保存接口、列表接口和页面上的保存与列表。

## 用户故事

- 作为登录用户，我希望把搜到的 GitHub 用户保存下来，以便之后查看和维护。
- 作为登录用户，我希望只看到自己保存的记录，以便数据不被其他账号看到或修改。

## 需求条目

| 编号 | 需求 | 优先级 |
|------|------|--------|
| R1 | 把搜索结果保存到数据库，内容以点击时 GitHub 返回的最新资料为准 | P0 |
| R2 | 同一账号不能重复保存同一个 GitHub 用户，改名后仍视为同一用户 | P0 |
| R3 | 显示当前账号保存的全部用户，按保存时间倒序 | P0 |
| R4 | 没有记录时显示空状态 | P1 |
| R5 | 每个账号只能看到自己的记录，接口未登录返回 401 | P0 |
| R6 | 保存和加载过程有状态提示并防止重复提交 | P1 |

### R1 保存

搜索结果旁有「保存用户」按钮。点击后接口重新向 GitHub 读取资料并写入数据库。成功后清空搜索结果，新记录出现在列表最前面。读取 GitHub 失败时，提示与搜索失败相同。

### R2 防重复

以 GitHub 用户的数字 ID 判重，同一账号重复保存时提示「该用户已保存」。不同账号可以各自保存同一个 GitHub 用户。

### R3 已保存列表

内容与搜索结果相同：头像、用户名（新标签页打开 GitHub 主页）、姓名、简介、所在地。资料中没有的项不显示。

### R4 空状态

没有记录时显示「还没有保存的用户。」

### R5 账号隔离

`githubProfiles.add`、`githubProfiles.list` 都需要登录，列表只返回当前账号的记录。

### R6 交互状态

列表首次加载时显示「正在加载…」；保存进行中「搜索」「保存用户」按钮禁用。保存错误显示在搜索区内，列表错误显示在列表区内，同一个错误只显示一次。

## 验收标准

- [x] AC1（R1）：搜索 `octocat` 后点「保存用户」，搜索结果清空，列表最前面出现 `@octocat`，刷新页面后仍在。
- [x] AC2（R2）：再次搜索并保存 `octocat`，提示「该用户已保存」，列表没有新增。
- [x] AC3（R2）：同一 `githubId` 换了 `username` 再保存，接口返回 CONFLICT。
- [x] AC4（R2）：账号 A 和账号 B 都能保存 `octocat`。
- [x] AC5（R3）：依次保存两个用户，后保存的排在前面。
- [x] AC6（R4）：没有记录的账号打开页面，显示「还没有保存的用户。」
- [x] AC7（R5）：账号 B 的列表看不到账号 A 保存的记录。
- [x] AC8（R5）：未登录调用 `add`、`list`，都返回 401。
- [x] AC9（R6）：保存进行中「搜索」「保存用户」按钮禁用；列表加载失败时，列表区内只出现一次提示，没有重复的 toast。
