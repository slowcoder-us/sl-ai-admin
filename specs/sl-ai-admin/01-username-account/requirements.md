# 用户名账号（注册 / 登录） - 需求

> 来源：`docs/登录需求.md` · 1 背景与目标、2.1 注册、2.2 登录、4 交互要求
> 依赖：无

## 背景

管理后台需要最基本的账号体系。现有脚手架用的是「邮箱 + 密码」，需求要求改为「用户名 + 密码」且不需要邮箱。本 feature 打通后端用户名账号能力，并完成 Web 端注册、登录表单；访问控制和退出由 02 负责，移动端由 03 负责。

## 用户故事

- 作为新用户，我希望用用户名和密码注册账号，注册完直接进入后台，以便马上开始使用。
- 作为已注册用户，我希望用用户名和密码登录，以便进入后台。

## 需求条目

| 编号 | 需求 | 优先级 |
|------|------|--------|
| R1 | 账号以用户名作为唯一登录标识，不需要用户填写邮箱 | P0 |
| R2 | 注册表单：用户名、密码、确认密码，前端校验并在输入框下方提示 | P0 |
| R3 | 注册成功后自动登录并跳转 `/dashboard` | P0 |
| R4 | 用户名已被注册时提示「用户名已被注册」 | P0 |
| R5 | 登录表单：用户名、密码；成功后跳转 `/dashboard` | P0 |
| R6 | 登录失败统一提示「用户名或密码错误」 | P0 |
| R7 | 提交时按钮显示加载状态，防止重复提交 | P1 |
| R8 | `/login` 默认显示登录表单，可切换到注册表单 | P0 |

### R1 用户名作为账号

- 用户名规则：3–20 位，只能包含字母、数字、下划线（`^[A-Za-z0-9_]+$`），全局唯一。
- 用户名**不区分大小写**：`Alice` 与 `alice` 视为同一账号；界面显示用户注册时的原始写法。
- 用户不填写邮箱。Better Auth 要求 email 必填，由系统按用户名自动生成占位邮箱（不校验、不发信、用户不可见、不能用于登录）。
- 规则在后端强制校验，前端校验只是提前提示。

### R2 注册表单校验

| 字段 | 规则 | 错误提示（输入框下方） |
|------|------|------------------------|
| 用户名 | 必填，符合 R1 规则 | 用户名格式不正确（3–20 位字母、数字或下划线） |
| 密码 | 必填，至少 8 位 | 密码至少 8 位 |
| 确认密码 | 必填，与密码一致 | 两次输入的密码不一致 |

### R3 注册后自动登录

注册接口成功即建立登录会话，前端跳转 `/dashboard`。

### R4 用户名重复

后端返回用户名已存在时，用 toast 提示「用户名已被注册」。大小写不同但相同的用户名同样视为重复。

### R5 登录

字段：用户名、密码（前端只校验非空）。成功后跳转 `/dashboard`。

### R6 登录失败提示

用户名不存在、密码错误，一律 toast 提示「用户名或密码错误」，不区分是哪一项。网络或服务异常提示「登录失败，请稍后重试」。

### R7 加载状态

提交中按钮禁用并显示加载文案（「登录中…」「注册中…」），请求结束后恢复。

### R8 登录页默认表单

`/login` 首次进入显示登录表单，底部链接切换注册表单，注册表单可切回登录。

## 非功能需求

- 安全：密码只经 Better Auth 存储（哈希）；占位邮箱不能作为登录入口（禁用邮箱登录接口）。
- 界面文字使用中文。

## 验收标准

- [x] AC1（R1）：注册 `Alice_01` 后数据库 `user` 表有 `username = alice_01`、`displayUsername = Alice_01`，email 为系统占位邮箱。
- [x] AC2（R1）：直接调用 `POST /api/auth/sign-up/email` 传 `username = "ab"` 或 `"a-b-c"`，返回错误，不创建用户。
- [x] AC3（R1）：调用 `POST /api/auth/sign-in/email` 返回 404（接口已禁用）。
- [x] AC4（R2）：用户名输入 `ab`、密码输入 `1234567`、确认密码输入 `x`，提交后三个输入框下方分别出现对应错误，不发请求。
- [x] AC5（R3）：输入合法新用户名和密码注册，跳转到 `/dashboard` 且处于登录状态。
- [x] AC6（R4）：用已注册的用户名（含仅大小写不同）再注册，toast 显示「用户名已被注册」。
- [x] AC7（R5）：用正确的用户名密码登录，跳转 `/dashboard`。
- [x] AC8（R6）：用不存在的用户名、或错误密码登录，toast 都显示「用户名或密码错误」。
- [x] AC9（R7）：提交过程中按钮为禁用状态并显示加载文案。
- [x] AC10（R8）：打开 `/login` 默认看到登录表单，可来回切换到注册表单。

## 不在范围内

- 已登录访问 `/login` 跳转、未登录访问 `/dashboard` 跳转、退出登录、后台首页显示用户名、接口 401：由 `02-web-access-control` 负责。
- 移动端注册登录：由 `03-native-username-auth` 负责。
- 忘记密码、邮箱注册/验证、第三方登录、手机号登录、记住我、角色权限（PRD 第 5 节）。

## 待确认问题

- 无（占位邮箱、用户名不区分大小写、中文界面已在 W2 确认）。
