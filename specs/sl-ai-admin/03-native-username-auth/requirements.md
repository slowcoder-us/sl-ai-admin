# 移动端用户名登录注册 - 需求

> 来源：`docs/登录需求.md` · 1 背景与目标（覆盖端：移动端 `apps/native`）、2.1 注册、2.2 登录、2.3 退出登录、2.4 访问控制、4 交互要求
> 依赖：01-username-account

## 背景

PRD 要求 Web 和移动端都支持账号体系。现有 Expo 应用把邮箱登录 / 注册卡片直接放在首页，未登录也能进入所有页面。本 feature 把移动端改为用户名 + 密码，并在未登录时只允许看到登录页。

## 用户故事

- 作为手机用户，我希望用用户名和密码注册、登录，以便在手机上使用后台。
- 作为未登录的手机用户，我打开 App 时应先看到登录页。
- 作为已登录的手机用户，我希望在右上角退出登录。

## 需求条目

| 编号 | 需求 | 优先级 |
|------|------|--------|
| R1 | 登录 / 注册页：默认登录表单，可切换注册表单 | P0 |
| R2 | 注册：用户名、密码、确认密码；校验规则和提示与 Web 一致；成功后自动登录进入首页 | P0 |
| R3 | 用户名已被注册时提示「用户名已被注册」 | P0 |
| R4 | 登录：用户名、密码；失败统一提示「用户名或密码错误」；成功进入首页 | P0 |
| R5 | 未登录时只能看到登录 / 注册页；已登录时不会再看到登录页 | P0 |
| R6 | 首页显示当前用户名；右上角可「退出登录」，退出后回到登录页 | P0 |
| R7 | 提交时按钮显示加载状态，防止重复提交 | P1 |

### R1 登录 / 注册页

独立页面（不在抽屉导航里），首次显示登录表单，底部链接切换注册表单。

### R2 注册

- 规则与提示语与 Web 完全一致（共用 `@sl-ai-admin/auth/credentials`）：用户名 3–20 位字母 / 数字 / 下划线，密码至少 8 位，确认密码一致。
- 校验错误显示在对应输入框下方。
- 成功后会话自动建立，界面切换到首页（相当于 Web 的 `/dashboard`）。

### R3 用户名重复

服务端返回用户名已存在（含仅大小写不同）时，toast 提示「用户名已被注册」。

### R4 登录

用户名或密码错误一律 toast「用户名或密码错误」；网络 / 服务异常 toast「登录失败，请稍后重试」。

### R5 访问控制

- 未登录：根导航只暴露登录 / 注册页，抽屉、Tabs、Modal 都不可达（包括通过深链接）。
- 已登录：登录 / 注册页不可达。
- 会话加载中显示加载指示，不闪现登录页。
- 需要登录的 tRPC 接口仍由服务端返回 401（02 已验证），移动端无需额外处理。

### R6 首页与退出

- 首页显示「欢迎，<用户名>」（`displayUsername`，没有时用 `username`），不显示邮箱。
- 抽屉页头右上角提供用户菜单 / 「退出登录」按钮；退出后清除 SecureStore 中的会话和查询缓存，界面回到登录页。

### R7 加载状态

提交中按钮禁用并显示加载指示，请求结束后恢复。

## 非功能需求

- 界面文字使用中文。
- 会话继续用 Better Auth Expo 插件存于 SecureStore（AGENTS.md 既有约定）。

## 验收标准

- [ ] AC1（R1）：未登录启动 App，看到登录表单，可切换到注册表单再切回。
- [ ] AC2（R2）：用户名 `ab`、密码 `1234567`、确认密码不一致，提交后三个输入框下方显示与 Web 相同的错误，不发请求。
- [ ] AC3（R2）：用新用户名注册成功后自动进入首页，显示「欢迎，<用户名>」。
- [ ] AC4（R3）：用已存在的用户名（含仅大小写不同）注册，toast「用户名已被注册」。
- [ ] AC5（R4）：错误密码或不存在的用户名登录，toast 都是「用户名或密码错误」；正确登录进入首页。
- [ ] AC6（R5）：未登录时通过深链接 `sl-ai-admin://two` 打开，仍停在登录页。
- [ ] AC7（R6）：点右上角「退出登录」后回到登录页；杀掉 App 重新打开仍是登录页。
- [ ] AC8（R7）：提交中按钮禁用并显示加载指示。
- [ ] AC9：`pnpm -F native check-types` 通过，`expo export` 打包 iOS 成功（证明共享模块能被 Metro 解析）。

## 不在范围内
