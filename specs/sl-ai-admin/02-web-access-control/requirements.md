# Web 访问控制与退出登录 - 需求

> 来源：`docs/登录需求.md` · 2.2 登录（已登录访问登录页）、2.3 退出登录、2.4 访问控制、3 页面
> 依赖：01-username-account

## 背景

01 完成后用户可以注册和登录，但后台页面还没有统一的登录拦截：登录页对已登录用户仍然可见，退出后回到首页而不是登录页，后台首页和用户菜单还显示邮箱。本 feature 补齐 Web 端的访问控制和退出流程。

## 用户故事

- 作为未登录的访客，我访问后台页面时应被带到登录页，以便先登录。
- 作为已登录用户，我打开登录页时直接进入后台，不用再登录一次。
- 作为已登录用户，我希望在右上角菜单里退出登录，以便在公共电脑上保护账号。

## 需求条目

| 编号 | 需求 | 优先级 |
|------|------|--------|
| R1 | 未登录访问 `/dashboard` 等后台页面时跳转 `/login` | P0 |
| R2 | 已登录访问 `/login` 时直接跳转 `/dashboard` | P0 |
| R3 | 右上角用户菜单显示用户名，点「退出登录」清除登录状态并回到 `/login` | P0 |
| R4 | 后台首页 `/dashboard` 显示当前用户名 | P0 |
| R5 | 需要登录的接口在未登录时返回 401（UNAUTHORIZED） | P0 |

### R1 后台页面拦截

- 「后台页面」指 `/dashboard` 及其子路径（本期只有 `/dashboard`，后续新增的后台页面放在其下即自动受保护）。
- 拦截在服务端完成，未登录时页面内容不会下发到浏览器。

### R2 登录页反向跳转

已登录（会话有效）访问 `/login`，服务端直接重定向 `/dashboard`。会话 cookie 存在但已失效时，正常显示登录页。

### R3 退出登录

- 用户菜单按钮文字为用户名（`displayUsername`，没有时用 `username`）。
- 菜单项：用户名（不可点）、「退出登录」。不再显示邮箱。
- 点击「退出登录」后：调用退出接口，清除前端缓存的会话与查询数据，跳转 `/login`。之后按浏览器后退回到 `/dashboard` 也会被 R1 拦回登录页。
- 未登录时菜单位置显示「登录」按钮，指向 `/login`。

### R4 后台首页

`/dashboard` 显示「欢迎，<用户名>」。

### R5 接口 401

`protectedProcedure` 在无会话时抛出 `UNAUTHORIZED`，HTTP 状态码为 401。现有实现已具备，本 feature 用测试固定下来。

## 非功能需求

- 界面文字使用中文。

## 验收标准

- [x] AC1（R1）：未登录直接打开 `/dashboard`，最终停在 `/login`。
- [x] AC2（R2）：登录后打开 `/login`，最终停在 `/dashboard`。
- [x] AC3（R3）：登录后右上角显示用户名；点「退出登录」后停在 `/login`，再访问 `/dashboard` 被拦回 `/login`。
- [x] AC4（R3）：未登录时右上角显示「登录」按钮，点击进入 `/login`。
- [x] AC5（R4）：以 `Alice_01` 登录后，`/dashboard` 显示「欢迎，Alice_01」。
- [x] AC6（R5）：不带 cookie 请求 `GET /trpc/privateData`，HTTP 状态码 401，错误 code 为 `UNAUTHORIZED`；带登录 cookie 请求返回 200。

## 不在范围内

- 注册、登录表单本身：`01-username-account`。
- 移动端：`03-native-username-auth`。
- 角色与权限（PRD 第 5 节）。
