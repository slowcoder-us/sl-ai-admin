# 云端部署

前端运行在 Cloudflare Workers，使用 OpenNext 构建 `apps/web`。Worker 将同源的 `/api/auth/*` 和 `/trpc/*` 转发至 AWS API Gateway HTTP API。API Gateway 调用运行 `apps/server` 的 Lambda。前端登录会话使用 Worker 域名上的 Cookie。

AWS CDK 在同一 VPC 中创建一个出网公有子网、两个应用私有子网和两个数据库隔离子网。应用流量经公有子网的 NAT Gateway 和 VPC 的 Internet Gateway 访问 GitHub。Aurora PostgreSQL Serverless v2 的 5432 端口仅对 Lambda 和 SSM 跳板机开放。GitHub 资料只保存到当前登录账号的列表，编辑的是本地副本。

## 首次部署

1. 在 Cloudflare **Workers & Pages** 确认账号的 `workers.dev` 子域名。当前 Worker 名为 `sl-ai-admin-web`，默认地址为 `https://sl-ai-admin-web.<子域名>.workers.dev`。记下地址和账户 ID。
2. 在目标 AWS 区域完成 CDK bootstrap。如果使用 CloudFormation 控制台，可以先运行 `pnpm -F @sl-ai-admin/infra cdk bootstrap --show-template > /tmp/sl-ai-admin-cdk-bootstrap.yaml` 导出官方模板，再在控制台上传为 `CDKToolkit` 堆栈。如果区域里已有默认限定符为 `hnb659fds` 的兼容 CDK bootstrap，可复用。
3. 在 AWS IAM 确认 GitHub OIDC provider，地址为 `https://token.actions.githubusercontent.com`，audience 为 `sts.amazonaws.com`。在同一个 AWS 区域用 [GitHub OIDC 模板](../packages/infra/github-oidc.yml) 创建 CloudFormation 堆栈，记下输出 `RoleArn`。模板的 `Repository` 参数使用 GitHub 的不可变 OIDC 格式 `owner@owner_id/repo@repo_id`，默认值对应本仓库。
4. 在 GitHub 仓库 **Settings → Environments** 创建 `production`，将部署分支限制为受信任的发布分支。添加下表中的环境变量和 Secret。AWS 授权通过 OIDC 使用短期凭证。
5. 把包含工作流的代码合并到 GitHub 默认分支。在 **Actions → Verify and deploy → Run workflow** 启动发布。工作流先跑测试，再用 CDK 部署 AWS 并应用 Prisma 迁移，接着发布 Worker 并检查登录页和经过 Worker 的 API。
6. 打开线上前端，登录后进入「后台 → GitHub 用户管理」。搜索 `octocat`，保存并修改姓名或简介，刷新后确认修改仍存在，再删除记录。

| GitHub 环境配置 | 类型 | 值 |
| --- | --- | --- |
| `AWS_REGION` | Variable | CDK bootstrap 和 Aurora 所在区域 |
| `AWS_DEPLOY_ROLE_ARN` | Variable | OIDC 模板的 `RoleArn` |
| `CLOUDFLARE_ACCOUNT_ID` | Variable | 目标 Cloudflare 账户 ID |
| `CF_WEB_ORIGIN` | Variable | Worker 的 HTTPS 地址，结尾省略斜杠 |
| `CLOUDFLARE_API_TOKEN` | Secret | 限定目标账号的 Workers Scripts 编辑凭证 |

## 通过跳板机管理数据库

从 CloudFormation 堆栈 `SlAiAdminBackend` 的 Outputs 读取 `BastionInstanceId`、`DatabaseEndpoint`、`DatabaseName` 和 `DatabaseAdminSecretArn`。管理员需拥有跳板机的 Session Manager 授权，使用 AWS CLI 和 Session Manager 插件建立转发。

```sh
aws ssm start-session \
  --target '<BastionInstanceId>' \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{"host":["<DatabaseEndpoint>"],"portNumber":["5432"],"localPortNumber":["15432"]}'
```

连接本地端口时将 TLS 校验的主机名保留为 Aurora 端点。使用 Secrets Manager 提供的数据库管理员凭证，录制时暂停凭证输入。

```sh
PGHOST='<DatabaseEndpoint>' PGHOSTADDR=127.0.0.1 PGPORT=15432 \
  PGSSLMODE=verify-full PGSSLROOTCERT='<RDS CA bundle path>' \
  psql -U sl_ai_admin -d sl_ai_admin
```

AWS 堆栈启用了数据库删除保护和快照保留。Aurora、NAT Gateway 和 EC2 跳板机运行期间会产生费用。

参考 [Cloudflare Next.js 部署文档](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/)、[GitHub Actions 的 AWS OIDC 配置](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-aws) 和 [AWS Session Manager 端口转发](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-working-with-sessions-start.html)。
