# 首页需求：GitHub 用户管理

## 1. 背景与目标

sl-ai-admin 管理后台需要一个 GitHub 用户管理功能：登录用户输入 GitHub 用户名，查到对方的公开资料，加入数据库，并能修改和删除已保存的记录。

覆盖端：Web（`apps/web`，即 app-view 模块，部署在 Cloudflare）、移动端（`apps/native`）。两端功能相同，操作的是同一份数据。

## 2. 功能范围

### 2.1 搜索 GitHub 用户

- 字段：GitHub 用户名（必填；最长 39 位，只能包含字母、数字和连字符，连字符不能在开头、结尾，也不能连续出现）。
- 搜索成功后显示：头像、用户名（点击打开该用户的 GitHub 主页，Web 在新标签页打开，移动端用系统浏览器打开）、姓名、简介、所在地。资料中没有的项不显示。
- 失败提示：
  - 用户名格式不正确：「请输入有效的 GitHub 用户名」
  - 用户不存在：「找不到该 GitHub 用户」
  - GitHub 限流：「GitHub 查询暂时受限，请稍后重试」
  - GitHub 不可用或超时：「暂时无法读取 GitHub 资料，请稍后重试」

### 2.2 加入数据库

- 搜索结果旁有「保存用户」按钮，点击后把该用户的资料保存到数据库。
- 保存的内容以点击时 GitHub 返回的最新资料为准。
- 保存成功后清空搜索结果，新记录出现在已保存列表最前面。
- 同一账号不能重复保存同一个 GitHub 用户，重复时提示「该用户已保存」。GitHub 用户改名后仍视为同一个用户。

### 2.3 已保存列表

- 显示当前登录账号保存的全部用户，按保存时间倒序排列，内容与 2.1 的搜索结果相同。
- 没有记录时显示「还没有保存的用户。」
- 每个账号只能看到和操作自己保存的记录。

### 2.4 修改

- 在列表中点「编辑」后，就地修改该条记录的姓名（最多 255 字）、简介（最多 500 字）、所在地（最多 255 字）。
- 三个字段都可以清空；用户名和头像不可修改。
- 点「保存修改」后更新数据库和列表；点「取消」不保存。

### 2.5 删除

- 在列表中点「删除」后，需要在该条记录上再点「确认删除」才真正删除；点「取消」则保留。
- 记录已不存在时（修改或删除）提示「找不到该记录」。

### 2.6 访问控制

- 未登录访问 GitHub 用户管理页时，跳转到登录页（移动端未登录时进不了该页面，深链接也不可达）。
- 本功能的全部接口（搜索、保存、列表、修改、删除）在未登录时返回 401（UNAUTHORIZED）。

### 2.7 部署

- Web 部署到 Cloudflare Workers，线上可以完成登录以及 2.1–2.5 的全部操作。
- 浏览器只访问 Web 自身的域名，`/trpc/*` 和 `/api/auth/*` 由 Web 转发到后端服务。
- 后端地址未配置或后端不可达时，转发返回错误状态码（未配置 503，不可达 502）。

## 3. 页面

| 页面 | 路径 | 说明 |
| --- | --- | --- |
| 后台首页 | `/dashboard` | 增加「GitHub 用户管理」入口 |
| GitHub 用户管理（Web） | `/dashboard/github-users` | 上方搜索用户，下方已保存用户列表 |
| GitHub 用户管理（移动端） | 抽屉菜单「GitHub 用户管理」 | 登录后可见，内容与 Web 相同，上方搜索用户，下方已保存用户列表 |

## 4. 交互要求

- 搜索、保存、修改、删除进行中，相关按钮禁用，防止重复提交；搜索和首次加载列表时显示加载状态。
- 错误提示显示在发生错误的区域内（搜索区、编辑表单、删除确认处）。
- 正在编辑或确认删除某条记录时，其他记录的「编辑」「删除」按钮禁用。
